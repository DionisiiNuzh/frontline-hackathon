# Hackathon Context

## Purpose

Store facts about the event and team constraints that shape all project work.

## Route here when

- checking rules, judging criteria, team responsibilities, deadlines, or constraints;
- recording verified event information.

Read the artifact relevant to the question. Modify only verified event or team context, and record provenance when practical. Product choices belong in `04_product/`; technical choices belong in `05_architecture/`; current execution status belongs in `_state/`. If an event fact is unknown, use `_research/` rather than guessing.

## Expected output

Concise, current constraints that downstream planning and decisions can cite.
